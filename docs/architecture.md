# 架构与目录约定

## 分层

```text
WebUI / CLI 入口
        |
        v
平台流程与编排器
        |
        v
common/ 共享能力
        |
        v
浏览器、邮箱、代理、验证码与下游服务
```

- 根目录入口负责解析参数和编排，不新增通用实现。
- `common/` 放可被两个及以上流程复用的 Python 模块。
- `tools/` 放人工触发的导出、校验、迁移和补传命令。
- `runtime/` 统一收纳根目录外的日志、状态和临时凭据。
- `schema/` 定义公开能力；`server/` 负责控制面 API、任务与界面，不复制平台业务逻辑。
- 独立 K12 适配器位于 `k12/`，拥有自己的服务、前端、任务和数据目录；`gmail_android/`、`vision_solver/` 等仍属于按需独立模块。

## 文件放置规则

新增代码时按以下顺序判断：

1. 用户直接运行的核心流程才放根目录。
2. 可复用业务能力放 `common/`。
3. 一次性维护命令放 `tools/`。
4. 测试放 `tests/`，不要在根目录创建 `test_*.py`。
5. 运行输出只能写入已登记的数据目录，不要生成新的根目录文件类型。

## 运行数据边界

运行数据可能包含个人信息或凭据，必须与源码分开：

| 类型 | 路径 |
|---|---|
| 邮箱池 | `emails.txt`、`outlook_accounts/`、`_outlook_pool/` |
| 会话与凭据 | `cookies/`、`tokens/`、`sso_output/` |
| 日志 | `runtime/logs/`、`tri_register_logs/` |
| 本地状态 | `runtime/state/` |
| 临时凭据 | `runtime/secrets/` |
| 截图与录屏 | `screenshots*/`、`recordings/` |
| 解锁结果 | `unlock_results/` |

这些路径必须保留在 `.gitignore`。目录需要进入仓库时只提交 `.gitkeep`，不能提交样本凭据。

## 控制面能力与配置

### 凭据提交与执行隔离（2.1.19）

真实入口为账号页的显式 RT 刷新或重新授权，以及 Work 签名授权任务。Python 拥有上游执行及当前凭据文件，Go 拥有任务、账号投影和签名回执；Core 的归属和业务账务不在 SG 修改。

状态机：queued → running → 上游结果持久保存 → 当前凭据发布 → 任务及账号投影同事务 succeeded。上游明确拒绝或没有可确认结果为 failed，提供重新授权；保存后的中断先恢复本次原结果，不能重新请求 RT。凭据已被后续操作更新时拒绝覆盖，失败记录保留原因。数据库短暂不可用时原任务显示收尾重试并自动继续，其他账号仍可执行；重启先处理原任务保存的结果，再处置无结果的中断任务。人工处理通过原账号资料修正、重新授权及 Work 原任务恢复入口完成。

任务、日志、账号列表及统计使用最多4个只读连接；写入仍保持原单连接事务，读取不占用写入连接。进程状态锁不包住数据库操作；发起和停止使用独立顺序锁，服务停止等待已启动任务收尾。IC 收码沿用已有独立索引库和连接池，不与任务库共用连接。本轮不改变 SG 存储引擎，也没有引入异步日志缓冲。

运行页显示实际 RT 刷新或重新登录授权、当前保存阶段、收尾重试次数和终态反馈。执行方式从原任务阶段记录读取，不因大量日志或收尾重试丢失。AT 测试保持只读；任务结束后日志区域不再把旧阶段显示成当前执行状态。失败可以从原运行页重新授权，已领取账号仍交由 Core 授权。

### 账号计数与原始来源

账号页按平台及规范化身份合并展示；同一个账号的导入资料、凭据文件和生产结果不重复计为多个账号。没有身份的记录保持独立，跨平台不合并。原始来源、凭据版本、托管绑定、任务和修复引用均不重写；展示行必须能展开全部原始来源并通过原引用查看详情。

读取状态机为首次读取/空列表/已加载 → 刷新中 → 更新成功或保留旧结果并可重试。总数与分页采用同一投影；可用、异常、待核验、已使用、处理中为互斥计数，总和必须等于身份数，来源记录数单列。任何同身份已领取/生产事实优先显示已使用；未结案刷新优先于健康状态。聚合读取不解除锁，不写业务或凭据。凭据修复、签名引用和回执仍按全部原始 ref 查找，不能从去重后的显示列表反查，否则旧订单会失去修复来源。

### 状态与恢复

- 页面按操作对象分离：`accounts/` 仅列账号、筛选、选择和发起；`checks/` 列持久批次与刷新历史；发起后及查看记录均进入独立 `runs/?batch=…` / `runs/?mode=refresh&task=…`，只显示本次进度、逐条结果、日志与恢复操作，返回保留筛选/分页。账号与历史页不内嵌运行区。旧检查明细链接保留原记录跳转到运行页。记录由服务端保存，关页或刷新浏览器不取消已受理工作。
- AT 检查：同一 request_id 原子建立任务与逐条记录 → queued → running → succeeded（检查结束，不代表每个 AT 有效）。单条 401/缺 AT 为 needs_refresh，不推断 RT、账号或订阅失效；网络/TLS 有界重试耗尽为 unknown，停止该批后续检查并保留未执行项。操作员可只重测未知/未执行项，新批关联原批，原结果不覆盖。
- 检查证据位于现有任务表及 `credential_check_items`，不存 Token，也不复制账号、库存或业务权威。单批最多 100 项，排队上限 20 批，单 worker 串行处理；AT 每项总时限 30 秒、网络/TLS/5xx 最多 3 次，429/401 不重试。其他平台原报告任务最多等待 90 秒，未确认则保留关联任务并停止该批后续项。
- 停止批次：queued → stopped；running → stopping → 当前只读请求收尾后 stopped。服务重启 → interrupted，原结果保留，未确认项可重测。API 检查执行器独立拥有此任务，普通 Python runner 不领取它。
- RT 刷新始终是独立显式操作，进入原刷新任务追踪；检查绝不调用 RT。其他平台既有报告核对能力保留并明确标记为历史报告，不伪称实时 AT 测试。无凭据内容写入检查记录。
- RT 刷新生命周期：按账号串行受理 → queued → running → 本次完整凭据和任务结案一致后 succeeded；没有可确认成功结果的已结束任务为 failed。已保存结果优先本地恢复，数据库结案短暂失败自动重试；无法恢复则保留失败证据并允许重新授权，不重复交换可能已消耗的 RT。历史 unknown 仍可由原任务核对或人工结案，不再新建无限期占用账号的未知任务。

- 发起任务：编辑 → 提交 → 受理 queued → running → success/failed/stopped。丢失提交响应保留 request_id，先核对原任务；确认未受理才以同一 ID 重发。同请求重放不重复启动。
- 外部动作：明确未产生副作用的失败可回传 failed；副作用未知保持 unknown、原任务和证据，交由原任务核对/人工恢复，不通过新建任务推断成功或失败。
- 账号刷新失败：Python 内部保留稳定的小写原因，只有带 `account.failure.v1` 标记、stdout 结构化事件中的允许原因才能进入签名回执；节点边界统一为 `WORK_ACCOUNT_` 加大写错误码，供 Core 映射安全说明。历史无标记事件仍返回 `WORK_ACCOUNT_REFRESH_FAILED`，保持原结果摘要。ChatGPT 凭据任务的 exit75 先恢复原保存结果，不能确认则失败并释放占用，下次改用重新授权。原始上游响应与登录资料不进入公开回执。
- 配置：读取 → 编辑 → 保存 → 回读确认；失败保留草稿，结果未知先回读。文件未设置与默认值分开显示，默认值不自动写入。
- 新 Python worker 启动时读取最新文件；已运行 worker 保留启动快照。真正部署环境变量仍优先。节点身份、签名密钥和 Go 进程级配置需重启，保存成功不等于已经生效。
- 列表首次读取、空结果、刷新中、刷新失败分别显示；失败保留旧记录及重试。轮询串行、有界、离页取消；统计在完整集合上完成后分页。

## 邮箱池管理

管理员在同一邮箱池入口管理 IC 地址、Outlook 和通用邮箱；后两者继续使用原账号存储，不复制凭据。IC 地址独立于收信存在，来源配置、收信取码、同步运行、邮箱设置分别为独立页面；新增、编辑、导入和清理在本页浮层完成。公开取码保留 Turnstile，管理接口使用面板认证。

- 地址：导入/收信发现 → active；管理员可暂停 paused 或阻止 blocked，再恢复 active。暂停/阻止在所有取码入口生效，收信证据仍保留。清理邮件不删除地址和手工状态。
- 来源：保存 → starting → running；连接错误显示具体错误并自动有界间隔重连。修改连接配置会先停止旧连接再启动新连接；停用后停止收信，重新启用可恢复。已有收信的账号、服务器、文件夹属于历史身份，替换时新建来源。
- 来源连接快照在消息和游标落库的同一写锁内核对；账号、服务器、端口或文件夹被替换后，旧连接不能写入新来源的邮件、游标或错误，原同步为 interrupted，新连接继续自动收信。
- 手工同步：同一 request_id 幂等受理 → pending → running → completed/failed；配置变更或进程停止为 interrupted，来源停用/删除的未执行请求为 cancelled。运行页保留来源、请求编号、开始/结束时间、新增邮件数及失败原因。丢响应先查询原编号，再以相同编号重发；终态重试使用新编号且不覆盖原记录。同步只读取上游邮件，重复执行按来源与 UID 去重，不重复产生邮件或统计。
- 自动收信继续由来源运行器负责，不要求管理员反复点击同步。连接初始时限30秒，每轮索引时限60秒；失败后至少间隔5秒重连。同步结果未确认时保留已写入证据，管理员可以在运行页再次同步。
- 消息、精确收件地址索引及旧计数在同一事务写入；跨来源相同 UID 可并存。历史别名状态和邮件只在结构升级时回填地址池，正常列表不再扫描所有邮件。IC 是 SG 原有的独立索引存储，不改变 Aishop Next 的 PostgreSQL 业务事实边界。
- 历史地址先统一大小写及首尾空格再合并状态；保留最新的手工状态和证据，同一时间优先保留限制较严格的状态，避免升级后暂停或阻止意外失效。清理仅通过 POST 执行，保留天数由服务端校验为 1–3650 天，清理不删除地址与手工状态。

## 账号当前凭据

账号按平台、规范化邮箱归拢，上游用户身份不得串用。已确认相同用户转入新工作区时，当前工作区随成功凭据整套更新，旧交付的业务权限仍由 Core 校验。原来源编号和任务结果保留引用意义；执行、修复、AT 测试和默认下载统一解析该身份最近一次成功保存的完整凭据，不再由旧文件名决定版本。账号复用继续更新当前资料，不新增账号计数。

状态机：queued → running → 上游成功且当前凭据原子保存 → succeeded；明确拒绝、超时、交换后中断、缺少完整成功工件等未确认成功的结束任务均为 failed，记录原因、释放账号占用，保留上一次成功凭据。新任务可以重新发起；RT 交换响应丢失后的新尝试自动走登录资料重新授权，不重复交换可能已消耗的 RT。相同账号的来源编号共用执行互斥，写回前核对源版本，过时结果不能覆盖新结果。`credential_updated_at` 只表示成功保存时间，扫描、失败和 AT 测试不推进它；历史无可靠时间时不编造时间。

验收：旧来源与新来源读取相同当前凭据；修复成功后旧来源下载和签名回传均为新值；明确失败保留旧值及时间并可重试；并发/过时回写受保护；不同工作区隔离；原任务结果和 Core 授权范围不被改写；40 个账号不因资料来源增加而重复计数。

成功任务在发布当前凭据前保存本次接收工件，原回执摘要不会随账号下次复用而变化。缺少本次成功工件时回传失败，不能把账号旧资料冒充新任务结果。运行配置与当前凭据分开，AT 测试不写凭据保存时间。

`tools/compact_credentials.py` 默认只预览；停止凭据执行后使用 `--apply`，将重复 OAuth 和旧 Free 文件收敛为引用和身份元数据，保留登录材料与原任务记录。写入当前资料后逐一验证所有旧引用再移除过期结果文件；执行中的刷新摘要和最近十分钟的接收材料保留。已结束任务不继续保留旧凭据副本，旧版本摘要不能再用于常规下载，调用方收到“凭据已更新”并下载当前版本。

读取列表、来源详情和下载只计算摘要，不生成结果副本。任务启动时才固定恢复输入，成功/失败或人工结案后释放该临时输入；原任务保留摘要与时间。Python 写回恢复材料保留到 Go 任务结案确认，再自动清理；清理失败保留私有材料和运维提示，不撤销已确认成功的任务。Work 尚需核验的本次任务回执与当前账号资料分开，账号复用不能改写旧回执。新 AT 测试取当前 AT，新刷新取当前 RT，新生产任务取当前资料；查询旧任务不读取当前凭据来重建旧结果。

- `file` 指向仓库内真实入口。
