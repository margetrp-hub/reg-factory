## 2.1.21 原任务收尾发行

原生产任务新增只读续权入口：管理员原因及原授权经 Core/Work 投递，SG 先持久停止，在原运行锁内更新核验材料与时间窗，不改变原输入范围、产物、调用次数或停止标记。正在执行的步骤先返回并保存；未知继续保留证据，超过核验窗口可沿原任务再次授权。已保存有效成品只读核对并沿原 custody 回传，原订单/库存/资金终态仍归 Core。

隔离 Python 生产 **19项通过**，覆盖正常生产、停止、暂时核验失败、原成品恢复、授权超期及续权。Go 全包通过，统一 Dockerfile 构建及非业务版本读取通过；本地完整 Go 检查使用同提交 Docker 构建生成的真实前端 embed。Linux 上以真实 Go HTTP handler 调用 Python 子进程并写入临时持久库，验证中文原因、原授权重放、同编号更改原因拒绝及 stop 保留。Linux 用例使用 `--network none`，没有访问真实上游；Windows 对依赖 Linux flock 的跨进程用例明确跳过，Linux 实跑结果单独计入。

异步阶段/日志保持原任务范围、签名、分页、持久去重与脱敏，Work 在关闭新派发时仍可采集原任务。接入和验收要求统一在[API](api.md)及 Core 的 `docs/contracts/work-node-integration.md`，不新增前端专用日志协议。

本次已发布不可变标签和服务器源码附件并部署到 SG；没有发行 Windows 便携桌面包。线上验证只读鉴权、健康、能力及原日志；没有验证真实客户生产、邀请、OAuth或线上超期任务的人工收尾，不能把隔离测试写成真实外部操作成功。
